# Nmap Detection Scenario

## Objective
The objective of this scenario is to detect reconnaissance activity performed through network scanning techniques using Nmap.

This simulation focuses on identifying suspicious enumeration behavior against internal network assets through firewall log analysis and SIEM correlation rules.
---
## Environment

All machines below are running in a virtualized lab environment using VirtualBox:

- Wazuh (SIEM)
- OPNsense (Firewall)
- Kali Linux (Attacker Machine)
- Linux Target Machine (Victim)
---
## Attack Simulation

The attacker machine is located in a permitted network segment and is allowed to communicate with the target environment through the firewall.

The main objective of the attacker is to enumerate services and open ports on the target machine without being detected by the SOC team.

The primary tool used during this scenario is Nmap, although other tools may be used in future tests to improve detection logic and rule analysis.
---
## Detection Process

The SOC uses correlation rules in Wazuh to identify suspicious scanning behavior based on firewall logs generated by OPNsense.

Detection flow:

Attacker performs Nmap scan  
↓  
OPNsense allows and logs the network connections  
↓  
Wazuh receives firewall events and analyzes the traffic behavior  
↓  
Rule `110001` identifies relevant firewall events  
↓  
Rule `110002` correlates multiple connection attempts from the same source IP within a short period of time  
↓  
Wazuh generates a reconnaissance alert for SOC analysis

The alert allows the SOC analyst to investigate the source IP, target ports, timestamps, and overall scanning behavior.
