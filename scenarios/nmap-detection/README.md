# Nmap Detection Scenario

## Objective
The objective of this scenario is to detect reconnaissance activity performed through network scanning techniques using Nmap.

This simulation focuses on identifying suspicious enumeration behavior against internal network assets through firewall log analysis and SIEM correlation rules.
---
## Environment

All machines below are running in a virtualized lab environment using VirtualBox:

- Wazuh (SIEM)
- OPNsense (Firewall)
- Kali Linux (Attacker Machine)
- Linux Target Machine (Victim)
---
## Attack Simulation

The attacker machine is located in a permitted network segment and is allowed to communicate with the target environment through the firewall.

The main objective of the attacker is to enumerate services and open ports on the target machine without being detected by the SOC team.

The primary tool used during this scenario is Nmap, although other tools may be used in future tests to improve detection logic and rule analysis.

---
## Detection Process

The SOC uses correlation rules in Wazuh to identify suspicious scanning behavior based on firewall logs generated by OPNsense.

Detection flow:

Attacker performs Nmap scan  
↓  
OPNsense allows and logs the network connections  
↓  
Wazuh receives firewall events and analyzes the traffic behavior  
↓  
Rule `110001` identifies relevant firewall events  
↓  
Rule `110002` correlates multiple connection attempts from the same source IP within a short period of time  
↓  
Wazuh generates a reconnaissance alert for SOC analysis

The alert allows the SOC analyst to investigate the source IP, target ports, timestamps, and overall scanning behavior.

The detection rule uses correlation logic based on:
- connection frequency;
- timeframe;
- same source IP address;
- different destination ports.

Multiple connection attempts from the same source IP within a short period of time may indicate reconnaissance activity or automated scanning behavior.

The rule also checks for different destination ports, which is commonly associated with service enumeration attempts.

## Bypass Techniques

An experienced attacker may attempt to understand how a SOC environment performs detection and adapt their behavior to reduce visibility or avoid correlation-based alerts.

In many scenarios, attackers attempt to generate less suspicious traffic patterns or exploit limitations in detection logic.

### Fragmented Packet Scan

One technique used to reduce detection visibility is packet fragmentation.

In Nmap, fragmented scans can be performed using the `-f` flag. This option splits packets into smaller fragments, which may reduce detection visibility depending on how the firewall, SIEM, or IDS processes network traffic.

In some environments, fragmented packets may affect correlation quality because logging systems can generate fewer consistent events for analysis.

### Decoy Scan

Another evasion technique is the use of decoy addresses.

Nmap supports this behavior using decoy scans, where multiple apparent source IP addresses are generated in an attempt to obscure the original attacker.

If detection logic relies heavily on conditions such as:

- multiple connections from the same source IP;
- connection frequency;
- source-based correlation;

then decoy traffic may reduce detection accuracy.

Example:

<img width="1603" height="670" alt="image" src="https://github.com/user-attachments/assets/d71ead0b-bc57-4319-9e7e-2b2693940b37" />

In this lab scenario, random decoy IPs were used.

Because the firewall only allows communication between trusted lab subnets, most decoy traffic was blocked and only the real attacker IP successfully reached the victim machine.

As a result, the correlation rule continued to function as expected.

A more realistic internal-network scenario using valid subnet ranges could potentially reduce rule effectiveness and deserves further testing.

### Time-Based Evasion

Another possible evasion technique involves reducing scan frequency.

Since the current detection logic is based on frequency and timeframe correlation, a low-and-slow scan may avoid detection by spreading requests over a longer period of time.

This scenario was not deeply tested because the rule logic is already known in this lab environment, making this bypass behavior predictable.

## Lessons Learned

- Correlation rules are effective for detecting high-frequency reconnaissance
- Firewall pass events may still indicate malicious behavior
- Fragmented packets can reduce detection visibility
- Detection quality depends on log consistency and correlation logic
- SIEM tuning is required to balance visibility and false positives
- Effective reconnaissance requires minimizing noise and adapting techniques to reduce detection visibility.
- Understanding defensive controls helps attackers modify behavior and test detection gaps during reconnaissance.

--
## Detection Limitations

The current detection logic relies heavily on frequency, timeframe, and source-IP correlation. More advanced evasion techniques or low-frequency scans may reduce detection effectiveness and require additional tuning.
