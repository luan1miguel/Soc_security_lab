# Web Enumeration Detection Scenario

## Objective

The objective of this scenario is to detect reconnaissance activity performed through web enumeration using common tools and scripts.

This simulation focuses on identifying suspicious enumeration behavior against web application assets through web server and firewall logs, combined with SIEM correlation rules.

---

## Attack Simulation

The attacker machine is located in a permitted network segment and is allowed to communicate with the target environment through the firewall.
The main objective of the attacker is to enumerate web paths and discover new application functionality that may be useful for further exploitation, without being detected by the SOC team.

In this scenario, tools such as FFUF, Dirb and Feroxbuster will be used. Other tools or custom scripts may be tested in future iterations to evaluate and improve the detection logic.
The detection logic is designed to identify enumeration behavior rather than relying exclusively on tool-specific signatures.

## Detection Process

The SOC uses multiple Wazuh correlation rules to identify suspicious web enumeration activity from WAF and web server logs.

### Behavioral Detection

The primary detection is based on the behavior generated by the enumeration itself:

Attacker performs web enumeration
↓
OPNsense allows and logs the network traffic
↓
WAF/Web server generates HTTP response logs
↓
Wazuh receives the events
↓
Rule `100101` identifies HTTP 404 responses
↓
Rule `100102` correlates multiple 404 responses from the same source IP within a short period
↓
Wazuh generates a potential web reconnaissance alert

### WAF-Based Detection

ModSecurity with OWASP CRS provides an additional detection layer.

Rule `100103` uses events generated by ModSecurity/OWASP CRS to identify known scanner-related patterns.

This provides an independent detection source from the behavioral correlation.
### Tool-Based Detection

When the attacker uses a known enumeration tool, additional indicators can be observed in the HTTP request.

Wazuh analyzes HTTP headers and User-Agent information.

Rule `100104` identifies known scanner signatures such as:

`dirb | dirbuster | gobuster | wfuzz | feroxbuster | ffuf | nikto | dirsearch`

This rule is mapped to MITRE ATT&CK `T1595.003 - Wordlist Scanning`.

### Correlated Detection

Rule `100105` correlates the WAF-based detection (`100103`) with the known scanner indicator (`100104`).

When both indicators are observed, the confidence of the web enumeration detection is increased.

The SOC can then investigate the source IP, requested paths, timestamps and overall request behavior before applying the appropriate response procedure.
